LINKCHECK PLUS — 10 November 2026

WHAT CHANGED
1. Watchlist / favourites
   - Authenticated Telegram users can save and remove approved projects.
   - Saved projects are stored per Telegram ID in SQLite.

2. Change history and notifications
   - The backend keeps a snapshot of public project-card fields.
   - A background task checks changes at a configurable interval (default 60 seconds; minimum 30 seconds, maximum 900 seconds).
   - Changes are added to project history and in-app notification inboxes for watchers and project owners.
   - The Mini App shows unread notifications and allows marking one or all as read.
   - Notifications are in-app; this release does not send Telegram direct messages or push notifications.

3. Catalog topics
   - Added topic taxonomy: News & Media, Finance & Banking, Government Services, Education, Technology, Shopping & Marketplaces, Entertainment, Other.
   - Topic can be selected when submitting or editing a project and filtered in the catalog.
   - Old clients that omit the topic field do not erase an existing topic.

4. Project history
   - Public history endpoint exposes only changed field names and timestamps for approved projects.
   - Historical JSON payloads remain server-side and are not returned by the public endpoint.

5. Owner analytics
   - Owner dashboard shows project count, catalog outbound visits, visits over the last 7 days, reports, pending reports and pending verification requests.
   - A viewer's repeated outbound clicks to the same project count at most once per UTC day.
   - Owners' own clicks are not counted.

6. Privacy
   - Updated Russian and English privacy policy to disclose watchlist, in-app notifications, public change history and aggregated outbound-visit analytics.

PRESERVED
- Existing catalog, checking, project submissions, moderation, reports, ownership review, OFFICIAL RESOURCE review, Telegram Verified and LINKCHECK badge logic remain in the source tree.
- Database changes are additive CREATE TABLE / CREATE INDEX statements. No existing project/user tables are dropped or recreated by these additions.

TESTS PERFORMED
- Python syntax check: passed.
- Inline JavaScript syntax check with Node.js: passed.
- SQLite integration smoke test: passed for idempotent initialization, watchlist add/remove, change notifications, read state, change history, unique visit counting, owner analytics, and compatibility with edit requests that omit topic.

LIMITATIONS
- This is a source-based best-effort release, not a live Bothost deployment test.
- Visit analytics counts authenticated catalog outbound clicks, not actual Telegram channel views, member growth, reach or unique lifetime people.
- The change monitor runs inside the single application process. Keep only one running instance using the same SQLite database and Telethon session.
